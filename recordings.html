Supported formats

Arduino: time_ms,dp_a_pa,...,dp_a_ok,... with the existing sketch header. Generic: time_s,pressure_pa or time_s,pressure. Optional valid uses 0/1. Room CSV: time_s,space_id,pressure_pa. Boundary CSV: time_s,positive_space_id,negative_space_id,pressure_pa. Time may also be time_ms. Other TEC export layouts need an explicit mapping first.

Analysis settings

Reported ΔP is positive endpoint minus negative endpoint. Confirm the physical hose mapping. IDs must match your BIM when exporting for comparison.

2.5 Pa is an example analysis limit. Review it for your test. It is not a universal safety or acceptance criterion.

The main twin supports up to 600 s; this analysis export uses a declared window of at most 60 s, rebased to zero. Full-recording analysis and JSON remain intact; align the model events to this window.

    Method and limitations

    Baseline uses the sample mean and sample standard deviation. Crossing times are estimated only between connected valid samples. The timeline uses the full recording duration.

    Pressure alone does not determine total airflow. A positive differential needs boundary orientation and design context before it can be interpreted as a reversal. No machine-learning model or automatic risk assessor is used.

    Generic inH₂O conversion uses 249.0889 Pa per conventional inH₂O. Confirm the instrument unit convention before quantitative validation.
